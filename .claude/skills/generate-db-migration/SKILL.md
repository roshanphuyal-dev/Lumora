# Generate Database Migration

## Objective
Produce a reviewable, reversible Alembic migration for a schema change, per `.claude/rules/database.md` and `docs/DATABASE.md#migration-conventions`.

## Inputs
- The SQLAlchemy model change (new table/column, altered constraint, etc.).
- Whether existing data needs backfill.

## Outputs
- Migration generated via `uv run alembic revision --autogenerate -m "..."`, then hand-reviewed and adjusted.
- `docs/DATABASE.md#core-tables` updated to reflect the new/changed table.

## Expected Quality
- Foreign keys have explicit `ON DELETE` behavior.
- New columns on non-empty tables are nullable-first (or have a safe default), with a follow-up migration to tighten constraints after backfill if needed.
- Destructive changes (drop column/table) include a rollback note in the migration docstring.

## Completion Checklist
- [ ] Autogenerated diff hand-reviewed, not blindly accepted.
- [ ] `ON DELETE` behavior explicit on new foreign keys.
- [ ] Safe for non-empty tables (nullable-first or defaulted).
- [ ] `docs/DATABASE.md` updated.
- [ ] Destructive changes documented with rollback steps.
