# ADR 0012: Internet Search Integration (Tavily/Brave)

## Status
Accepted

## Context
`docs/ROADMAP.md` Phase 3 names "Internet search integration (Tavily/Brave)" as a line item — the last piece of Phase 3 alongside topic image retrieval (`ADR 0010`). No `TaskType.INTERNET_SEARCH` exists yet in the orchestrator, and no code in `ai/` talks to a web search provider.

Two things need deciding before implementation: which provider(s) to use, and how a search result becomes a student-facing answer without bypassing this codebase's existing grounding/synthesis philosophy (`.claude/rules/ai.md`: web content is untrusted data, never instructions, in any prompt).

Unlike `ADR 0010`'s image providers (Wikimedia/Openverse, both free/keyless), no comparably-featured keyless web search API exists — this is a real deviation from the "prefer keyless" precedent set by `ADR 0008` (OpenCode Zen fallback, no billing) and `ADR 0010` (Wikimedia/Openverse, no billing), and is called out explicitly rather than smoothed over.

## Decision
Use **Tavily Search API** as primary, **Brave Search API** as an optional fallback, for `TaskType.INTERNET_SEARCH`.

**Route**: Tavily basic search (`include_answer=false`, retrieval mode) → Brave LLM Context fallback (only if `BRAVE_SEARCH_API_KEY` is configured; otherwise a Tavily failure returns an explicit "search unavailable" result, not a silent Brave attempt) → Gemini synthesizes the final student-facing answer from the normalized results. Search results are never returned directly as the answer.

**Provider comparison**:
- **Tavily** — free Researcher plan, 1,000 API credits/month, no credit card required (1 credit = 1 basic search). Pay-as-you-go $0.008/credit; paid plans $0.0075–$0.005/credit at higher tiers. Production keys require an active paid plan or PAYGO. Rate limits: 100 req/min (dev key), 1000 req/min (production). Auth: Bearer token (`TAVILY_API_KEY`). Returns structured JSON — ranked results with title/URL/relevance score/content, `response_time`, optional `include_raw_content`. Supports an `include_answer` mode that returns an LLM-generated answer directly — deliberately not used here (see Decision below on synthesis). Latency: no independently verified p50/p95; the provider's own example shows 1.67s but that isn't a guarantee. Privacy: the FAQ claims "zero data retention" and SOC 2 certification, but the actual privacy policy (updated 2025-11-24) says Tavily collects query data, may use portions to improve future responses unless the contract says otherwise, may forward queries to third-party index providers in limited cases, and has no concrete query-specific deletion period (purpose-based retention only). This inconsistency is **unresolved** — see Tradeoffs.
- **Brave** — Search (including Web Search and LLM Context) costs $5 per 1,000 requests; $5/month free credit ≈ 1,000 free calls. Answers costs $4/1000 queries plus token costs (not used here). Advertised capacity 50 req/sec. A payment card is mandatory even for free-tier use (anti-fraud verification per Brave, not charged on the free plan) — more billing friction than Tavily's no-card free plan. Auth: `X-Subscription-Token` header (`BRAVE_SEARCH_API_KEY`). The LLM Context endpoint returns pre-extracted, relevance-ranked grounding material by URL (titles/snippets/metadata) explicitly designed for a caller-controlled LLM pipeline — a good match for "Gemini synthesizes" since it isn't a pre-answered response. Latency: an older provider comparison page claims 95% of requests under 1 second, but this isn't a current, independently-verified SLA. Privacy: retains API query records up to 90 days for billing/troubleshooting/abuse-prevention/legal reasons; states it doesn't collect end-user identifiers connecting a query to a person and argues API query data isn't "personal data" under GDPR on that basis — but Lumora can still associate a search with a user/conversation on its own side, so Lumora remains responsible for notice/minimization/lawful-basis/deletion regardless of Brave's position. True zero-data-retention is Enterprise-only, not the default. **Constraint**: Brave's standard Search API terms prohibit storing/caching Search Results beyond transient storage needed to operate the application — longer-lived caching requires a plan with explicit storage rights. This directly constrains the caching design below.

**Synthesis pass**: `TaskType.INTERNET_SEARCH` always returns normalized grounding results for Gemini to synthesize — never a provider-generated answer passed straight through — even though both providers offer an "answer" mode. Bypassing the "search then Gemini" policy would move pedagogical judgment into a search provider, produce inconsistent behavior depending on which provider answered, add hidden LLM cost inside the search provider, and make citation/prompt-injection handling provider-dependent instead of centralized in the orchestration layer. This matches `.claude/rules/ai.md`: web content is untrusted data, never instructions, in any prompt.

**Caching**: no AI-response cache layer exists anywhere in this codebase yet — this is genuinely new infrastructure, not reuse of an existing one. Cache key = `hash(normalized_query + provider + max_results + freshness params)`. Normalization: trim/collapse whitespace, casefold, but preserve punctuation/dates/quoted phrases/domain filters (these change search meaning). TTL: short (5–15 min) for Tavily results, given the current-events use case. Brave results must **not** be persistently cached at all, per its terms — transient/request-scoped only, or skip caching Brave results entirely. This per-provider asymmetry is a real implementation constraint, not a detail to smooth over.

**Integration shape**: `ai/internet_search/` package — `schemas.py` for the provider-neutral `InternetSearchResult`/`InternetSearchItem` contract, `tavily_client.py`, `brave_client.py` (each the only place that provider's HTTP calls happen, per `.claude/rules/ai.md`). `TaskType.INTERNET_SEARCH` added to `ai/orchestrator/task_types.py`; `orchestrator.py` owns provider ordering/fallback/Gemini synthesis. Client method shape: `async search(query, *, max_results=5, freshness=None, include_domains=(), exclude_domains=()) -> InternetSearchResult`. Never log raw query text, response bodies, API keys, or student-linked identifiers. Respect provider rate-limit/`Retry-After` headers rather than blind retry.

## Alternatives Considered
- **Brave as primary instead of Tavily** — rejected: mandatory billing enrollment even for the free tier is more friction than Tavily's no-card free plan, contradicting this codebase's stated keyless/low-friction preference (`ADR 0008`, `ADR 0010`), even though Brave has stronger published privacy documentation.
- **Using provider "answer" modes (Tavily `include_answer` / Brave Answers) as the default path instead of a Gemini synthesis pass** — rejected per the synthesis-pass reasoning above: it would move pedagogical judgment and citation handling out of the centralized orchestration layer and make behavior provider-dependent.
- **A general-purpose AI-response cache framework instead of a minimal helper scoped to this feature** — rejected as premature, per this codebase's anti-speculative-abstraction stance (`CLAUDE.md`); build only what's needed now.

## Tradeoffs
- Tavily's privacy-policy ambiguity (FAQ "zero data retention" vs. the actual policy's purpose-based retention and third-party forwarding) is a real open item, **not resolved by this ADR** — flagged as an explicit pre-production gate requiring written clarification/DPA from Tavily before sending real student-derived queries.
- Brave's no-persistent-caching term means the two providers can't share one uniform caching policy — the implementation must be provider-aware (short-TTL cache for Tavily, transient-only or no cache for Brave).
- Neither provider is keyless, unlike `ADR 0010`'s image providers — local dev requires signing up for both Tavily and (optionally) Brave API keys, a real cost relative to that precedent.

## Consequences
- `ai/internet_search/`, `TaskType.INTERNET_SEARCH`, and the new endpoint must be added to `docs/AI.md`'s routing table and `docs/API.md` when implemented, per `.claude/rules/documentation.md` (mirrors `ADR 0010`'s Consequences).
- Before production use with real student data, the Tavily privacy-policy ambiguity must be explicitly resolved (written clarification/DPA) — this is a hard pre-production gate, not a nice-to-have.
- Any future caching-layer work (`docs/TOKEN_OPTIMIZATION.md`) that generalizes beyond this feature must preserve the per-provider caching asymmetry (Tavily short-TTL vs. Brave transient/no-cache) rather than flattening it into one policy.
- `BRAVE_SEARCH_API_KEY` is optional at runtime — its absence must degrade to "search unavailable" on Tavily failure, not silently skip fallback in a way that looks like a bug.
