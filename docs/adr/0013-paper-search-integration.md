# ADR 0013: Paper Search Integration (arXiv/Semantic Scholar)

## Status
Accepted

## Context
`docs/ROADMAP.md`'s Phase 3 Definition of Done explicitly calls out the gap this ADR closes: "research paper search isn't covered by either search provider" — `TaskType.INTERNET_SEARCH` (`ADR 0012`) is general web search, and `TaskType.IMAGE_SEARCH` (`ADR 0010`) is topic imagery; neither indexes academic literature. No `TaskType.PAPER_SEARCH` exists yet, and no code in `ai/` talks to a scholarly-paper provider.

The same two questions from `ADR 0012` recur: which provider(s), and how a result becomes a student-facing answer without moving pedagogical judgment or citation handling out of the orchestration layer (`.claude/rules/ai.md`: external content is data, never instructions, in any prompt).

## Decision
Add `TaskType.PAPER_SEARCH`. Use the **arXiv API** as primary, **Semantic Scholar Academic Graph API** as an optional fallback, gated on `SEMANTIC_SCHOLAR_API_KEY` being configured.

**Route**: arXiv search (`export.arxiv.org/api/query`) → Semantic Scholar fallback (only if `SEMANTIC_SCHOLAR_API_KEY` is configured) → Gemini synthesizes a cited answer from the normalized results. This is the **identical shape** to `TaskType.INTERNET_SEARCH` (`ADR 0012`) rather than a structured reading list — an explicit decision made this session for UI/pattern consistency across the two search features (see Alternatives).

**Provider comparison**:
- **arXiv (primary)** — fully keyless, no authentication. Rate limit: 1 request/3 seconds, one connection at a time (~0.33 req/sec), no published daily cap. Atom 1.0 XML response: title, published/updated dates, summary (abstract), ordered author list, abstract-page link, PDF link, categories, optional DOI/journal-ref. Coverage: arXiv e-prints only, across 8 subject areas (CS, Economics, EESS, Math, Physics, Q-Bio, Q-Finance, Statistics) — strong for STEM, no medicine/law/humanities/journal-only coverage. arXiv explicitly **permits** storing/transforming/sharing descriptive metadata (titles, abstracts, authors, identifiers, classifications) and recommends caching repeated queries, saying there's no need to re-query more than once/day since results only change when new articles are added. arXiv explicitly does **not** permit storing/serving PDFs or source files without the paper's own copyright license allowing it — store metadata + outbound PDF URLs only, never proxy/persist PDFs. Attribution required: display "Thank you to arXiv for use of its open access interoperability," no branding implying endorsement.
- **Semantic Scholar (optional fallback)** — API key optional but recommended; unauthenticated calls share a common pool with no reserved/predictable capacity (current numeric limit unpublished); a dedicated key (`x-api-key` header) gets an individual 1 request/second allocation, no published daily cap either way. Structured JSON, selectable fields: title, abstract (nullable — omitted for some publishers, e.g. Springer, per official release notes), authors, year/publicationDate, venue/journal, citationCount, url, isOpenAccess, openAccessPdf (nullable). Coverage: 200M+ papers via publisher partnerships/data providers/web crawls, spanning medicine/law/humanities/CS/physics and multiple publication types — far broader than arXiv. **License gate**: the default API license grants use for "internal use for legitimate research or educational purposes" only; commercial use requires an expanded license from Semantic Scholar/AI2. Public display requires linking back with `utm_source=api` plus the Semantic Scholar name/logo. Prohibits selling/leasing/sublicensing/commercializing the data. No published cache-TTL or explicit no-cache rule, but the public-display/commercial-use conditions make persistent storage/redistribution a legal question, not a code decision. Query privacy/retention (logging, retention period) is unstated in official materials — unverified either way.

**Empty-result handling**: mirrors `_run_internet_search`'s actual current behavior exactly (`ai/orchestrator/orchestrator.py`), which has **no special case for zero results**. A provider call that succeeds but returns an empty result list is treated identically to a non-empty success — the empty list is still passed straight to Gemini for synthesis, with no fallback triggered and no "no results" short-circuit. Fallback to the secondary provider is triggered only by an exception from the primary provider, never by an empty-but-successful result. `_run_paper_search` must follow this exact pattern: an empty arXiv result (zero papers found) is not treated as a failure and does not by itself trigger a Semantic Scholar fallback attempt — only a raised provider error does. This keeps the two search task types behaviorally consistent, per this ADR's synthesis-shape decision, and avoids inventing new empty-result semantics that `INTERNET_SEARCH` doesn't have.

**Integration shape**: new `ai/paper_search/` package, mirroring `ai/internet_search/`'s structure exactly — `schemas.py` for the provider-neutral `PaperSearchProvider`/`PaperSearchItem`/`PaperSearchResult` contract (`PaperSearchItem`: `title`, `authors: tuple[str, ...]`, `abstract` (nullable), `publication_date` (nullable), `url`, `pdf_url` (nullable), `venue` (nullable), `citation_count` (nullable — arXiv never provides this)), `arxiv_client.py`, `semantic_scholar_client.py`, `cache.py`. `TaskType.PAPER_SEARCH` added to `ai/orchestrator/task_types.py`; `orchestrator.py` owns provider ordering/fallback/Gemini synthesis via a new `ai/prompts/paper_search_synthesis_v1.py`, using the same untrusted-external-content framing as `internet_search_synthesis_v1.py`, adjusted for paper metadata instead of web snippets. Rate-limit handling must be provider-aware — arXiv's 1 req/3sec single-connection limit and Semantic Scholar's 1 req/sec-with-key-plus-backoff-on-429 are different enough that a single generic retry policy would violate one or the other's documented limits.

## Alternatives Considered
- **Semantic Scholar as primary instead of arXiv** — rejected: arXiv is fully keyless with zero license ambiguity for the primary path, matching this codebase's keyless-preference (`ADR 0008`, `ADR 0010`) far better than Semantic Scholar's license-gated broader coverage. Keeping the license-clean provider as primary means the feature works out of the box in dev with no gate, with Semantic Scholar as a strictly opt-in broadening.
- **A structured reading-list response instead of Gemini synthesis** — this was the initial recommendation from this session's research (a distinct UX goal: browsing/selecting papers vs. one prose answer), but explicitly **rejected** in favor of matching `INTERNET_SEARCH`'s shape exactly, for UI/pattern consistency between the two search features. Recorded here so a future revision isn't surprised by the tradeoff (see Tradeoffs).
- **No Semantic Scholar fallback at all (arXiv-only)** — rejected: ship it config-gated behind the license question rather than omit it, consistent with how Brave was handled in `ADR 0012` (built, but gated) rather than `ADR 0010`'s fully-keyless Wikimedia/Openverse-only approach.

## Tradeoffs
- arXiv's STEM-only corpus means a paper-search query about, e.g., a history or law topic will find little or nothing from the primary provider even when Semantic Scholar (broader) would have results — a real coverage gap that persists while Semantic Scholar stays gated pending its license resolution.
- Semantic Scholar's license ambiguity is a second, independent legal gate alongside Tavily's (`ADR 0012`) — both documented, neither blocks the arXiv-only dev-scope path.
- Matching `INTERNET_SEARCH`'s synthesis-only shape means a student browsing for papers gets one Gemini-written answer with citations rather than a scannable list of paper options — a real UX tradeoff, accepted here for pattern consistency rather than silently smoothed over.

## Consequences
- `ai/paper_search/`, `TaskType.PAPER_SEARCH`, and the new endpoint must be added to `docs/AI.md`'s routing table and `docs/API.md` when implemented, per `.claude/rules/documentation.md` (mirrors `ADR 0012`'s Consequences).
- Before enabling Semantic Scholar with real student data, its default non-commercial license (this codebase's product is commercial ed-tech) must be explicitly resolved — written clarification or an expanded license from Semantic Scholar/AI2. This is a hard pre-production gate for the Semantic Scholar path specifically, structurally identical to `ADR 0012`'s Tavily privacy-policy gate, and is the user's action item to resolve, not something this ADR resolves.
- `SEMANTIC_SCHOLAR_API_KEY` is optional at runtime — its absence must degrade to arXiv-only ("search unavailable" only if arXiv itself fails), never silently attempt Semantic Scholar unauthenticated as a substitute for the gate, and never fail loudly just because the key is unset.
- Implementers must not persistently cache Semantic Scholar results (no published cache-TTL/no-cache rule, but public-display/commercial-use license terms make persistence a legal question); arXiv results may be cached per its own stated once-per-day-is-enough guidance, mirroring `ADR 0012`'s per-provider caching asymmetry (Tavily short-TTL vs. Brave transient/no-cache) rather than flattening it into one policy.
- Empty-result handling for `_run_paper_search` must stay behaviorally identical to `_run_internet_search`'s actual current behavior (no special-casing of empty-but-successful results, fallback triggered only by provider exceptions) — a future change to one search task type's empty-result semantics should prompt re-checking the other for drift.
