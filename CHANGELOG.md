### Changed
- Global `QueryClient` no longer retries 4xx errors (`frontend/src/App.tsx`) — the default retried every failure up to 3 times with backoff, so a 404 (e.g. an unowned/deleted notebook) left the page stuck on its loading state for several extra seconds before showing the real error.
- Deleting a notebook now removes its cached detail query (`queryClient.removeQueries`) instead of invalidating a broad `["notebooks"]` prefix that also matched and refetched the just-deleted notebook's own detail query, 404ing pointlessly before the page navigated away.
- `apiFetch`/`apiFetchForm` (`frontend/src/lib/api.ts`) now attempt one silent token refresh on a 401 (`POST /auth/refresh`, using the stored refresh token) and retry the original request before giving up — an access token expires in 30 minutes (`ACCESS_TOKEN_EXPIRE_MINUTES`) and a refresh token is already issued and stored on login; previously any 401 force-logged-out immediately regardless. Concurrent 401s share one refresh call instead of each racing their own. `AuthProvider`'s `isAuthenticated` (`frontend/src/hooks/use-auth.tsx`) now derives from `token-storage.ts` via `useSyncExternalStore` instead of separate local state, so a token change made outside `signIn`/`signOut` (this refresh, or a failed-refresh logout) is reflected immediately — previously `clearTokens()` called from `api.ts` didn't update the provider's state at all, leaving the UI showing "authenticated" with no valid tokens until an unrelated re-render happened to notice.

### Fixed
- `apiFetch`/`apiFetchForm` (`frontend/src/lib/api.ts`) called `.json()` unconditionally on every successful response — a `204 No Content` (every `DELETE` endpoint) has no body, so the first delete/detach action in the app would have thrown a JSON parse error. Found and fixed before it shipped (delete notebook / remove source, this same round of work).
- `backend/app/core/config.py` now calls `load_dotenv()` at import time so `backend/.env` populates the real process environment, not just the `Settings` pydantic model — `ai/gemini/client.py` and `ai/opencode_zen/client.py` read their API keys via `os.environ.get(...)` directly and previously wouldn't see them unless exported in the shell.
- `test_storage.py`'s Supabase-credential tests no longer depend on the developer's real `backend/.env` having no `SUPABASE_*` values set — they now monkeypatch `get_settings` to an explicit unconfigured stub.
- Celery worker: `documents.parse_document`/`notebooks.index_source` tasks failed with `NoReferencedTableError` on `documents.subject_id` — the worker process only imports the model modules its task functions directly touch, so SQLAlchemy's mapper registry never saw `Subject` and couldn't resolve the cross-table FK. `app/workers/celery_app.py` now imports every model module at startup (same pattern as `backend/tests/conftest.py`).
- Celery worker: running a second DB-touching task in the same worker process raised `RuntimeError: Future attached to a different loop` — each task wraps its work in its own `asyncio.run()`, but both tasks shared the app-wide pooled `engine`, and asyncpg connections are bound to the event loop that created them. Added a separate `celery_session_maker` (`app/db/session.py`, `NullPool`) so no DB connection ever crosses a loop boundary; `document_tasks.py`/`notebook_tasks.py` now use it instead of the FastAPI-request-scoped session maker.
