## [Unreleased]

### Added
- Project documentation and Claude Code workspace scaffold (`docs/`, `.claude/`, `AGENTS.md`, `CONTRIBUTING.md`).
- Backend scaffold (FastAPI + SQLAlchemy async + Alembic) with `users`, `courses`, `subjects` tables and their first migration.
- Auth API: register, login, Google ID-token login, refresh — JWT access + refresh token pair.
- Courses API: create/list courses and subjects, scoped to the authenticated user, `limit`/`offset` pagination.
- Local dev Postgres via `docker/docker-compose.yml`.
- `documents`, `notebooks`, `notebook_sources` tables and their migration.
- Document API: upload (multipart, dispatches async parsing), paginated list, detail (parse status + extracted text poll target), delete — scoped to the uploading user.
- Document parsing pipeline: PDF/PPTX/DOCX/image-OCR parsers (`backend/app/parsers/`) run via a Celery task, with a local-disk `FileStorage` stopgap ahead of real Supabase Storage wiring.
- Notebook API: CRUD plus attach/detach document sources, dispatching NotebookLM indexing via Celery — scoped to the owning user.
- AI orchestration layer (`ai/orchestrator/`): `task_type`-based routing for `document_index` (→ NotebookLM) and `teaching_explanation` (→ Gemini 2.5 Flash, live via `google-genai`).
- `redis` service added to `docker/docker-compose.yml` (Celery broker).
- Real Supabase Storage integration (`backend/app/core/storage.py`: `SupabaseFileStorage`, via `supabase-py`) — `get_file_storage()` uses it when `SUPABASE_URL`/`SUPABASE_SERVICE_ROLE_KEY` are set, otherwise falls back to the local-disk `FileStorage` stopgap (dev/test default).
- Real NotebookLM CLI integration (`ai/notebooklm/client.py`) replacing the always-fails stub: shells out to the `nlm` CLI (`notebooklm-mcp-cli`) to create/reuse a notebook's remote NotebookLM id and upload/index source documents. Requires a one-time interactive `nlm login` per machine running the Celery worker (`docs/DEPLOYMENT.md`); not yet verified against a live authenticated `nlm` profile (`docs/DECISIONS.md#known-debt-not-yet-adr-worthy`).
- `notebooks.notebooklm_notebook_id` column + migration, caching the remote NotebookLM notebook id per `Notebook`.
- OpenCode Zen provider client (`ai/opencode_zen/client.py`) and Gemini <-> OpenCode Zen fallback for `TaskType.TEACHING_EXPLANATION` (`ai/orchestrator/orchestrator.py`) — if Gemini is unavailable, rate-limited, or its daily quota is exhausted, the orchestrator falls back to a free OpenCode Zen model, and vice versa (ADR 0008).
- Frontend scaffold (`frontend/`): Vite + React + TypeScript, Tailwind CSS v4, shadcn/ui (new-york style), React Router, TanStack Query, Framer Motion, React Hook Form. Design tokens (emerald accent, zinc neutral, Source Serif 4 + Inter, dark mode) wired per `docs/UI_UX.md`.
- Dashboard shell (`frontend/src/pages/DashboardPage.tsx`, `frontend/src/components/layout/AppShell.tsx`): sidebar app-shell, honest Phase-1-scoped empty states (upload CTA, empty notebooks list), and a quiet "coming soon" ledger for weak-topics/progress/streaks sections that have no real backend yet. `DESIGN.md` records the resulting design system.
- Auth pages (`frontend/src/pages/LoginPage.tsx`, `RegisterPage.tsx`): email/password login and registration (register auto-logs-in), wired to the real `/api/v1/auth` endpoints. Token storage (`frontend/src/lib/token-storage.ts`), an `AuthProvider`/`useAuth` context, and a `RequireAuth` route guard that redirects unauthenticated visits to `/login` — the dashboard route is now actually protected instead of always rendering. Google login rendered as a disabled "Soon" control (`GOOGLE_CLIENT_ID` isn't configured yet, per `docs/SECURITY.md`).
- Dashboard's "Your notebooks" section (`frontend/src/components/dashboard/NotebooksSection.tsx`) now fetches real data from `GET /api/v1/notebooks` (TanStack Query, `frontend/src/hooks/use-notebooks.ts`) with explicit loading/error/empty/populated states — verified end-to-end against a running backend, including a real created notebook rendering in the list.
- "Upload material" now does the real upload flow (`frontend/src/hooks/use-upload-source.ts`, `frontend/src/components/dashboard/UploadSourceCard.tsx`): multipart upload → poll `GET /api/v1/documents/{id}` for `parse_status` → create a notebook named from the file → attach the document as its source. There's no combined upload+notebook endpoint (docs/AI_WORKFLOWS.md keeps them separate steps), so the frontend orchestrates it as one flow to match the dashboard's existing "upload a document to create your first notebook" copy. Verified end-to-end against a running backend + Celery worker.
- Notebook detail page (`frontend/src/pages/NotebookDetailPage.tsx`, route `/notebooks/:id`): notebook name/description plus a sources ledger with per-source indexing status (`Pending`/`Indexed`/`Failed`, icon + color, `Indexed` using Confirmed Green for the first time — real success state, not a placeholder). Dashboard notebook rows now link here instead of being inert. Verified end-to-end including a real `Indexed` source (`nlm` CLI is now set up in this environment) and the not-found/not-owned state.
- Link resources: `documents` can now be link-backed (`source_url`, mutually exclusive with `storage_path` via a CHECK constraint) instead of only uploaded files, plus optional `title`/`description` resource metadata on any document. `POST /api/v1/documents/url` registers a link and dispatches the same async parsing pipeline, which fetches the page (`backend/app/parsers/url_parser.py`, stdlib `html.parser` text extraction — no new dependency) instead of downloading from storage. NotebookLM indexing (`backend/app/workers/notebook_tasks.py`) writes the document's already-extracted text to a temp file for link-backed documents rather than trying to download nonexistent storage bytes.
- Notebook detail page now has **Resources**/**Ask** tabs (`frontend/src/components/ui/tabs.tsx`, shadcn) instead of a flat sources section — "Resources" is the sources ledger, relabeled, with a new "Add resource" button. `NotebooksListPage.tsx` gained a "+ New notebook" card opening the same dialog (`frontend/src/components/notebook/ResourceDialog.tsx`, using new `dialog.tsx`/`textarea.tsx` shadcn primitives) that asks for a notebook title/description and one or more resources (file upload or link, toggled per row) up front. Both flows share `frontend/src/hooks/use-submit-resources.ts` (create-or-attach orchestration: upload/create-url → poll parse → attach — no combined backend endpoint, same client-side-orchestration precedent as the dashboard's existing upload flow).
- "Ask" tab is now a real multi-turn chatbox (`frontend/src/components/notebook/AskNotebookSection.tsx` + new `frontend/src/components/notebook/chat/`), still against the existing single-turn, non-streaming `/ask` endpoint — conversation held in local React state only, one request per turn, no server-side context between turns (full streaming + persisted history spec'd but deferred to Phase 2, `docs/adr/0009-ai-chat-streaming-persistence-export.md`). Adds: rich rendering (`MessageRenderer`) — GFM tables/lists (`remark-gfm`), inline/block LaTeX via KaTeX (`remark-math`, `rehype-katex`, `katex`), syntax-highlighted code blocks with a copy button (`rehype-highlight`, `CodeBlock`), safe images/links; output sanitized (`rehype-sanitize`, schema extended for KaTeX/highlight markup) so AI-generated Markdown can't inject scripts. Per-message memoization keeps prior messages from re-rendering when a new one arrives. Citations (when the answer is grounded) now rendered per message instead of silently dropped, per `.claude/rules/ui.md`. Messages are individually selectable (`use-chat-selection`) with "Select all"/"Clear selection"; an **Export** control (`ChatExport`) exports the selection or the full conversation to an A4 PDF (`chat-export.ts`, `jspdf` + `html2canvas-pro`, both dynamically imported only when exporting) with header/footer/page numbers, generated from the already-rendered chat DOM rather than raw Markdown. Uses `html2canvas-pro` rather than stock `html2canvas` (which throws on this app's oklch()-based Tailwind v4 colors) and rasterizes the DOM into sliced page images itself rather than jsPDF's own `doc.html()` (whose internal text-color resolution also chokes on oklch(), silently producing a blank-looking PDF) -- verified against real multi-page, multi-message exports.
- Google login is now real on the frontend, closing the last Phase 1 auth gap — the backend endpoint (`POST /auth/google`) already worked, but the button was a disabled "Soon" placeholder with no client-side flow at all. `GoogleLoginButton` (`frontend/src/components/auth/GoogleLoginButton.tsx`) loads Google's Identity Services script directly (no new npm dependency — it's a plain `<script>`, not an SDK package) and renders Google's own button; the resulting ID token goes straight to the existing `signIn`/`loginWithGoogle` flow shared with email/password login. Added to both Login and Register pages (Register had no Google option before at all). Renders nothing if `VITE_GOOGLE_CLIENT_ID` isn't configured, rather than a broken/fake button. Verified end-to-end short of the actual Google OAuth consent screen (no live client ID in this environment) — honest no-render confirmed, API contract confirmed against the real backend schema.
- Settings page (`frontend/src/pages/SettingsPage.tsx`, route `/settings`) closes the other Phase 1 gap: the backend's `GET`/`PATCH /users/me` existed with zero frontend UI. Shows email (read-only) and an editable full name, wired to real endpoints (`frontend/src/lib/users.ts`, `use-me`/`use-update-profile` hooks, matching the existing notebooks.ts/use-notebook.ts convention). `Settings` nav item flipped from disabled "Soon" to a real link in both the desktop sidebar and mobile header (`AppShell.tsx`). Verified end-to-end against the real backend, including a page-reload persistence check.
- Dashboard's "Add your first source" upload card replaced with the same "+ New notebook" create dialog used on the Notebooks list page (`ResourceDialog` mode="create") — one create-notebook flow instead of two different ones. The now-orphaned `UploadSourceCard`/`use-upload-source` (file-upload-only flow) are removed.
- Ask tab's message list and input are now a fixed-height chat panel (`AskNotebookSection.tsx`): only the message history scrolls internally, the input row stays visible below it regardless of scroll position — a plain CSS `sticky` input was tried first and rejected (it only stays visible once already near the bottom of a long conversation; scrolling up through history scrolls it away entirely, not the "always visible" behavior wanted).

### Fixed
- "Ask" on a notebook now actually reads the notebook's uploaded sources instead of answering blind. `ask_question` previously called Gemini with an always-empty `context`, so an indexed source made no difference to the answer. It now retrieves a grounded answer + citations from NotebookLM first (`TaskType.NOTEBOOK_QUERY`, `ai/notebooklm/client.py:query_notebook`) whenever the notebook has an `indexed` source, and hands that to Gemini as context for teaching-framed phrasing; falls back to the previous ungrounded call if there's no indexed source yet or the NotebookLM call fails. `NotebookAskResponse` now carries `citations`.
- `POST /api/v1/notebooks/{id}/ask` (`backend/app/services/notebook_service.py`, `backend/app/schemas/notebook.py`): a plain (ungrounded — no RAG yet, `docs/ROADMAP.md` Phase 4) teaching-explanation question via the AI orchestration layer, Gemini with OpenCode Zen fallback (ADR 0008). Scoped to notebooks the caller owns; 502 if every provider fails.
- "Ask a question" on the notebook detail page (`frontend/src/components/notebook/AskNotebookSection.tsx`): single-turn question/answer against the new `ask` endpoint, answer rendered as real Markdown (`react-markdown`, new dependency — the raw `**bold**`/`##`/table syntax was unreadable as plain text). Explicitly labeled as not source-grounded.
- Delete notebook (`frontend/src/components/notebook/DeleteNotebookButton.tsx`) and remove-source (per source row on the notebook detail page): two-step inline confirm for delete, no modal (`.claude/rules/ui.md`). Both wired to the existing `DELETE /notebooks/{id}` and `DELETE /notebooks/{id}/sources/{source_id}` endpoints.
- Full Notebooks list page (`frontend/src/pages/NotebooksListPage.tsx`, route `/notebooks`) — the sidebar's "Notebooks" nav item is a real, enabled route now instead of "Soon". List rendering shared with the dashboard's "Your notebooks" section via a new `NotebookList` component rather than duplicated.
- `backend/scripts/seed_test_user.py` — idempotent script creating a fixed `test@lumora.dev` / `testpass123` account for local manual testing without registering every time. Reuses `auth_service.register_user` rather than reimplementing hashing/persistence.

### Changed
- Global `QueryClient` no longer retries 4xx errors (`frontend/src/App.tsx`) — the default retried every failure up to 3 times with backoff, so a 404 (e.g. an unowned/deleted notebook) left the page stuck on its loading state for several extra seconds before showing the real error.
- Deleting a notebook now removes its cached detail query (`queryClient.removeQueries`) instead of invalidating a broad `["notebooks"]` prefix that also matched and refetched the just-deleted notebook's own detail query, 404ing pointlessly before the page navigated away.
- `apiFetch`/`apiFetchForm` (`frontend/src/lib/api.ts`) now attempt one silent token refresh on a 401 (`POST /auth/refresh`, using the stored refresh token) and retry the original request before giving up — an access token expires in 30 minutes (`ACCESS_TOKEN_EXPIRE_MINUTES`) and a refresh token is already issued and stored on login; previously any 401 force-logged-out immediately regardless. Concurrent 401s share one refresh call instead of each racing their own. `AuthProvider`'s `isAuthenticated` (`frontend/src/hooks/use-auth.tsx`) now derives from `token-storage.ts` via `useSyncExternalStore` instead of separate local state, so a token change made outside `signIn`/`signOut` (this refresh, or a failed-refresh logout) is reflected immediately — previously `clearTokens()` called from `api.ts` didn't update the provider's state at all, leaving the UI showing "authenticated" with no valid tokens until an unrelated re-render happened to notice.

### Fixed
- `apiFetch`/`apiFetchForm` now distinguish "the server rejected the request" (a real `ApiError` with a specific message) from "the server was never reached at all" (backend not running, wrong port, CORS) — the latter previously surfaced as a raw `TypeError` that every `error instanceof ApiError` check in the UI fell through on, showing a generic "Something went wrong" with no actionable detail. Now throws `ApiError(0, "Can't reach the server at <url> — check that the backend is running (see START.md).")` instead.
- `apiFetch`/`apiFetchForm` (`frontend/src/lib/api.ts`) called `.json()` unconditionally on every successful response — a `204 No Content` (every `DELETE` endpoint) has no body, so the first delete/detach action in the app would have thrown a JSON parse error. Found and fixed before it shipped (delete notebook / remove source, this same round of work).
- `backend/app/core/config.py` now calls `load_dotenv()` at import time so `backend/.env` populates the real process environment, not just the `Settings` pydantic model — `ai/gemini/client.py` and `ai/opencode_zen/client.py` read their API keys via `os.environ.get(...)` directly and previously wouldn't see them unless exported in the shell.
- `test_storage.py`'s Supabase-credential tests no longer depend on the developer's real `backend/.env` having no `SUPABASE_*` values set — they now monkeypatch `get_settings` to an explicit unconfigured stub.
- Celery worker: `documents.parse_document`/`notebooks.index_source` tasks failed with `NoReferencedTableError` on `documents.subject_id` — the worker process only imports the model modules its task functions directly touch, so SQLAlchemy's mapper registry never saw `Subject` and couldn't resolve the cross-table FK. `app/workers/celery_app.py` now imports every model module at startup (same pattern as `backend/tests/conftest.py`).
- Celery worker: running a second DB-touching task in the same worker process raised `RuntimeError: Future attached to a different loop` — each task wraps its work in its own `asyncio.run()`, but both tasks shared the app-wide pooled `engine`, and asyncpg connections are bound to the event loop that created them. Added a separate `celery_session_maker` (`app/db/session.py`, `NullPool`) so no DB connection ever crosses a loop boundary; `document_tasks.py`/`notebook_tasks.py` now use it instead of the FastAPI-request-scoped session maker.
- Notebook "Ask" was completely broken: every real Gemini call failed with `404 NOT_FOUND` ("model models/gemini-2.5-flash is no longer available to new users"). Google retired `gemini-2.5-flash` for new/unused API keys ahead of its official shutdown date. `ai/gemini/client.py` now targets `gemini-3.5-flash`, confirmed live against the real Gemini API (not just docs) as the current working stable flash-tier model for this project's key.
