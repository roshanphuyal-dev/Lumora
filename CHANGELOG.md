## [Unreleased]

### Added
- Notes tab extended from 2 to 7 material types, closing the remaining `docs/FEATURES.md` "Study Material Generator" gap (cheat sheets, formula sheets, mnemonics, timelines, comparison charts — nothing in that catalogue is unbuilt anymore). All seven `NoteMaterialType` values share the existing Notes generation pipeline (ownership, async Celery generation, NotebookLM grounding, status polling) but split into two output shapes: `note`/`study_guide`/`cheat_sheet`/`formula_sheet` stay Markdown in `notes.content` (unchanged), while `mnemonics`/`timeline`/`comparison_chart` are new — Gemini structured output (`response_schema`, no OpenCode Zen fallback since 3 different free-text shapes weren't worth the fragility) via a new `TaskType.STRUCTURED_NOTE_GENERATION`, stored in a new `notes.content_json` JSONB column (migration `5d81c8fe607b`, plus the 5 new enum values — Postgres has no `ALTER TYPE ... DROP VALUE`, so the migration's `downgrade()` documents that limitation rather than faking reversibility). Mnemonics/timeline render as a list (timeline gets a real vertical-line visual treatment); comparison chart renders as an actual `<table>`. Live-verified end-to-end for all 5 new types against real Gemini output.
- Theme mode (Settings > Appearance): Light/Dark/System, respecting `prefers-color-scheme` by default with a manual override, plus four selectable accent colors (emerald/blue/purple/rose) — both persisted to `localStorage` only, matching this app's existing per-browser-preference pattern (`AppShell.tsx`'s sidebar-collapsed state), per `docs/UI_UX.md`'s Dark Mode spec. A pre-paint inline script in `index.html` applies the stored preference before first render to avoid a flash of the wrong theme on reload. Accent colors only override the brand-color tokens (`--primary`/`--ring`/`--sidebar-primary*`), not shadcn's neutral hover-state tokens.
- Flashcards now render as an actual one-card-at-a-time deck (click/tap or Enter/Space to flip question↔answer, Prev/Next buttons plus ←/→ arrow keys, a position counter) instead of a two-column table — the table read poorly as a study format; the flip respects `prefers-reduced-motion` per `.claude/rules/ui.md`.
- NotebookLM Studio artifact generation — audio overviews, reports, slide decks, infographics, mind maps, and data tables — closing the FEATURES.md gap flagged after Phase 2 shipped (mind maps/cheat sheets/infographics/slides/reports/audio summaries were listed under "Study Material Generator" but not built). Unlike Notes/Flashcards, these are 100% NotebookLM-authored with no Gemini synthesis step and no ungrounded fallback — a notebook needs at least one indexed source (409 otherwise). New `generated_materials` table (migration `ec638c027c98`, one polymorphic table per `docs/DATABASE.md`'s reserved slot rather than six near-duplicate tables), new `ai/notebooklm/client.py` methods (`create_studio_artifact`/`get_studio_artifact_status`/`download_studio_artifact`, live-verified against real NotebookLM notebooks: `report` settles in ~6s, `infographic` in ~90s, `mindmap` uniquely returns its full result synchronously with nothing to poll or download), and a new `TaskType.STUDIO_ARTIFACT_CREATE` orchestration task — only the generation-trigger call goes through the orchestrator; polling and downloading are direct `NotebookLMClient` calls from the Celery task (`app/workers/studio_tasks.py`), mirroring the existing `ensure_remote_notebook` precedent for notebook-level bookkeeping rather than a new "AI does something" call. Text results (`report` markdown, `mindmap` JSON) are stored directly; binary results (`audio` mp3, `slides` pdf, `infographic` png, `data_table` csv) are downloaded from NotebookLM and re-uploaded into this app's own `FileStorage` — never left pointing at a NotebookLM-hosted URL — served back through an auth-scoped download endpoint, never a raw path or public bucket. New Studio API (`/notebooks/{id}/studio`, `docs/API.md`) and a new **Studio** tab on the notebook detail page: type-specific generation forms, settled-state polling, sanitized Markdown/collapsible-tree/audio-player/image previews per type, authenticated blob downloads, inline two-step delete confirmation.
- AI-generated notes/study guides and flashcards, closing the last Phase 2 gap (`docs/ROADMAP.md`). New `notes`, `flashcard_sets`, `flashcards` tables (migration `ccb307816929`), scoped to the owning user and notebook; generation is async (Celery, mirrors the existing document/NotebookLM-indexing task pattern) — creating a note or flashcard set returns immediately with `status=pending`, and the client polls until it settles to `done`/`failed`. Pipeline (`docs/AI_WORKFLOWS.md#1`/`#2`): NotebookLM retrieval for grounded content + citations when the notebook has an indexed source, then Gemini structures it — markdown for notes/study guides (`TaskType.NOTES_GENERATION`, `ai/prompts/note_generation_v1.py`), or a JSON `{front, back, citation}` list via Gemini's structured-output API (`response_schema`) for flashcards (`TaskType.FLASHCARD_GENERATION`, `ai/prompts/flashcard_generation_v1.py`) — both falling back to OpenCode Zen on any Gemini failure (ADR 0008; the flashcard fallback best-effort-parses plain `Q:`/`A:` text since OpenCode Zen has no structured-output API). New Notes API (`/notebooks/{id}/notes`) and Flashcards API (`/notebooks/{id}/flashcard-sets`), both paginated (`docs/API.md`). Notebook detail page gained **Notes** and **Flashcards** tabs: generate/list/view, settled-state polling, grounded citations shown per note/card, sanitized Markdown note rendering, inline two-step delete confirmation, and explicit loading/error/empty states throughout.
- Real multi-turn AI chat, closing the Phase 2 gap left by the Phase 1 single-turn `AskNotebookSection` (`docs/adr/0009-ai-chat-streaming-persistence-export.md`, now Accepted). New `conversations`/`messages` tables (migration `4c92ea8ada77`), scoped to the owning user and notebook, with per-message `provider` and `citations` (JSONB) so grounding survives per turn. New Chat API (`docs/API.md`): `POST`/`GET /notebooks/{id}/conversations`, `GET .../messages`, and `POST .../messages/stream` — a `text/event-stream` SSE endpoint (`start`/`delta`/`done`/`error` events) routed through a new `TaskType.CHAT_RESPONSE` orchestration task (`ai/orchestrator/orchestrator.py`): Gemini token streaming (`GeminiClient.stream_chat_response`, `ai/prompts/chat_response_v1.py`) with a non-streaming OpenCode Zen fallback if Gemini fails before its first token. Each turn is grounded against NotebookLM when the notebook has an indexed source, with bounded conversation history sent per turn (`docs/TOKEN_OPTIMIZATION.md` budget: last 20 messages, 12k chars). `AskNotebookSection.tsx` now creates/reuses a persisted conversation, loads its history, and streams responses token-by-token (appending only to the in-flight assistant message, per ADR 0009) instead of holding chat state in memory only — the existing Markdown/KaTeX/code rendering pipeline and PDF export carry forward unchanged.

### Fixed
- "Ask" on a notebook now actually reads the notebook's uploaded sources instead of answering blind. `ask_question` previously called Gemini with an always-empty `context`, so an indexed source made no difference to the answer. It now retrieves a grounded answer + citations from NotebookLM first (`TaskType.NOTEBOOK_QUERY`, `ai/notebooklm/client.py:query_notebook`) whenever the notebook has an `indexed` source, and hands that to Gemini as context for teaching-framed phrasing; falls back to the previous ungrounded call if there's no indexed source yet or the NotebookLM call fails. `NotebookAskResponse` now carries `citations`.
- `POST /api/v1/notebooks/{id}/ask` (`backend/app/services/notebook_service.py`, `backend/app/schemas/notebook.py`): a plain (ungrounded — no RAG yet, `docs/ROADMAP.md` Phase 4) teaching-explanation question via the AI orchestration layer, Gemini with OpenCode Zen fallback (ADR 0008). Scoped to notebooks the caller owns; 502 if every provider fails.
- "Ask a question" on the notebook detail page (`frontend/src/components/notebook/AskNotebookSection.tsx`): single-turn question/answer against the new `ask` endpoint, answer rendered as real Markdown (`react-markdown`, new dependency — the raw `**bold**`/`##`/table syntax was unreadable as plain text). Explicitly labeled as not source-grounded.

### Changed
- Global `QueryClient` no longer retries 4xx errors (`frontend/src/App.tsx`) — the default retried every failure up to 3 times with backoff, so a 404 (e.g. an unowned/deleted notebook) left the page stuck on its loading state for several extra seconds before showing the real error.
- Deleting a notebook now removes its cached detail query (`queryClient.removeQueries`) instead of invalidating a broad `["notebooks"]` prefix that also matched and refetched the just-deleted notebook's own detail query, 404ing pointlessly before the page navigated away.
- `apiFetch`/`apiFetchForm` (`frontend/src/lib/api.ts`) now attempt one silent token refresh on a 401 (`POST /auth/refresh`, using the stored refresh token) and retry the original request before giving up — an access token expires in 30 minutes (`ACCESS_TOKEN_EXPIRE_MINUTES`) and a refresh token is already issued and stored on login; previously any 401 force-logged-out immediately regardless. Concurrent 401s share one refresh call instead of each racing their own. `AuthProvider`'s `isAuthenticated` (`frontend/src/hooks/use-auth.tsx`) now derives from `token-storage.ts` via `useSyncExternalStore` instead of separate local state, so a token change made outside `signIn`/`signOut` (this refresh, or a failed-refresh logout) is reflected immediately — previously `clearTokens()` called from `api.ts` didn't update the provider's state at all, leaving the UI showing "authenticated" with no valid tokens until an unrelated re-render happened to notice.

### Fixed
- `apiFetch`/`apiFetchForm` now distinguish "the server rejected the request" (a real `ApiError` with a specific message) from "the server was never reached at all" (backend not running, wrong port, CORS) — the latter previously surfaced as a raw `TypeError` that every `error instanceof ApiError` check in the UI fell through on, showing a generic "Something went wrong" with no actionable detail. Now throws `ApiError(0, "Can't reach the server at <url> — check that the backend is running (see START.md).")` instead.
- `apiFetch`/`apiFetchForm` (`frontend/src/lib/api.ts`) called `.json()` unconditionally on every successful response — a `204 No Content` (every `DELETE` endpoint) has no body, so the first delete/detach action in the app would have thrown a JSON parse error. Found and fixed before it shipped (delete notebook / remove source, this same round of work).
- `backend/app/core/config.py` now calls `load_dotenv()` at import time so `backend/.env` populates the real process environment, not just the `Settings` pydantic model — `ai/gemini/client.py` and `ai/opencode_zen/client.py` read their API keys via `os.environ.get(...)` directly and previously wouldn't see them unless exported in the shell.
- `test_storage.py`'s Supabase-credential tests no longer depend on the developer's real `backend/.env` having no `SUPABASE_*` values set — they now monkeypatch `get_settings` to an explicit unconfigured stub.
- Celery worker: `documents.parse_document`/`notebooks.index_source` tasks failed with `NoReferencedTableError` on `documents.subject_id` — the worker process only imports the model modules its task functions directly touch, so SQLAlchemy's mapper registry never saw `Subject` and couldn't resolve the cross-table FK. `app/workers/celery_app.py` now imports every model module at startup (same pattern as `backend/tests/conftest.py`).
- Celery worker: running a second DB-touching task in the same worker process raised `RuntimeError: Future attached to a different loop` — each task wraps its work in its own `asyncio.run()`, but both tasks shared the app-wide pooled `engine`, and asyncpg connections are bound to the event loop that created them. Added a separate `celery_session_maker` (`app/db/session.py`, `NullPool`) so no DB connection ever crosses a loop boundary; `document_tasks.py`/`notebook_tasks.py` now use it instead of the FastAPI-request-scoped session maker.
- Notebook "Ask" was completely broken: every real Gemini call failed with `404 NOT_FOUND` ("model models/gemini-2.5-flash is no longer available to new users"). Google retired `gemini-2.5-flash` for new/unused API keys ahead of its official shutdown date. `ai/gemini/client.py` now targets `gemini-3.5-flash`, confirmed live against the real Gemini API (not just docs) as the current working stable flash-tier model for this project's key.
